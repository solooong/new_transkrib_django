# 🚀 Новые возможности версии 3.0

## 📋 Обзор изменений

В версии 3.0 реализованы три ключевые фичи для повышения гибкости и масштабируемости:

1. **Динамическое управление настройками** через django-constance
2. **Добавление скриптов "на лету"** через модель ProcessingScript
3. **Ролевая модель** для подготовки к личному кабинету

---

## 1️⃣ Динамическое управление настройками (django-constance)

### Что это?

Теперь ключевые настройки можно изменять **через админку Django без перезапуска контейнера**.

### Доступные настройки

В админке появился раздел **"Constance"** с двумя группами настроек:

#### Настройки транскрибации
- `DEFAULT_LANGUAGE` — Язык транскрибации по умолчанию (ru)
- `DEFAULT_MODEL` — Модель Whisper по умолчанию (whisper-large-v3)
- `ENABLE_DIARIZATION` — Включить диаризацию по умолчанию (True)
- `TASK_TIMEOUT_MINUTES` — Таймаут выполнения задачи в минутах (60)

#### Настройки системы
- `MAX_CONCURRENT_TASKS` — Максимальное количество одновременных задач (1)
- `RUNNER_SECRET` — Секрет защиты callback-API runner'а

### Как использовать

1. Откройте админку: `http://localhost:8000/admin/`
2. Перейдите в раздел **"Constance"**
3. Измените нужные параметры
4. Нажмите **"Сохранить"**
5. Настройки применятся **мгновенно** без перезапуска!

### Пример кода

```python
# В views.py, utils.py и других модулях
from constance import config

# Вместо os.environ.get('MAX_CONCURRENT_TASKS')
max_tasks = config.MAX_CONCURRENT_TASKS

# Вместо os.environ.get('RUNNER_SECRET')
secret = config.RUNNER_SECRET

# Вместо settings.DEFAULT_LANGUAGE
language = config.DEFAULT_LANGUAGE
```

## 2️⃣ Добавление скриптов "на лету"

### Что это?

Теперь можно **загружать новые скрипты транскрибации через админку** без изменения кода и перезапуска контейнера.

### Как это работает

1. **Модель ProcessingScript** хранит метаданные скриптов в БД
2. **Файлы скриптов** сохраняются в директорию `./scripts/` (volume)
3. **Пользователь** выбирает скрипт при создании задачи
4. **Runner** динамически запускает выбранный скрипт

### Как добавить новый скрипт

1. Откройте админку: `http://localhost:8000/admin/`
2. Перейдите в раздел **"Скрипты транскрибации"**
3. Нажмите **"Добавить скрипт транскрибации"**
4. Заполните поля:
   - **Название**: например, "Whisper Medium"
   - **Файл скрипта**: загрузите `.py` файл (например, `whisper_medium.py`)
   - **Описание**: опишите модель и особенности
   - **Название модели**: например, "whisper-medium"
   - **Активен**: включите, чтобы скрипт был доступен
   - **Скрипт по умолчанию**: включите, если хотите использовать по умолчанию
5. Нажмите **"Сохранить"**

### Использование в задачах

При создании задачи теперь можно выбрать скрипт:

```python
# В форме создания задачи
script = models.ForeignKey(
    "ProcessingScript",
    on_delete=models.SET_NULL,
    null=True,
    blank=True,
    verbose_name="Скрипт транскрибации"
)
```

Если скрипт не выбран, используется скрипт по умолчанию.

### Примеры скриптов

Можно создать разные скрипты для разных моделей:

- `whisper_large.py` — Whisper Large V3 (высокое качество, медленно)
- `whisper_medium.py` — Whisper Medium (баланс качества и скорости)
- `whisper_base.py` — Whisper Base (быстро, но менее точно)
- `whisper_turbo.py` — Whisper Large V3 Turbo (быстро и качественно)

### Безопасность

- Скрипты сохраняются только в директорию `./scripts/`
- Runner проверяет, что путь к скрипту находится в разрешённой директории
- Только суперпользователи и операторы могут загружать скрипты

## 3️⃣ Ролевая модель (подготовка к ЛК)

### Что это?

Реализована система ролей для разграничения доступа:

### Роли

#### 👤 Клиенты
- Видят **только свои задачи**
- Не могут управлять скриптами
- Не могут изменять системные настройки
- Используют интерфейс для создания задач

#### 👨‍💼 Операторы
- Видят **все задачи** всех пользователей
- Могут **управлять скриптами** (добавлять, редактировать, удалять)
- Могут **изменять системные настройки** через Constance
- Не могут удалять пользователей

#### 🔑 Суперпользователи (администраторы)
- Полный доступ ко всем функциям
- Могут управлять пользователями и группами
- Могут удалять скрипты и задачи

### Как назначить роль

1. Откройте админку: `http://localhost:8000/admin/`
2. Перейдите в раздел **"Пользователи"**
3. Выберите пользователя
4. В поле **"Группы"** добавьте нужную группу:
   - "Клиенты" — для обычных пользователей
   - "Операторы" — для администраторов контента
5. Нажмите **"Сохранить"**

### Автоматическое создание групп

При первом запуске автоматически создаются группы:
- **"Клиенты"** — с правом просмотра своих задач
- **"Операторы"** — с правами управления задачами и скриптами

### Фильтрация в админке

```python
# В TaskAdmin
def get_queryset(self, request):
    qs = super().get_queryset(request)
    if request.user.is_superuser:
        return qs  # Суперпользователь видит всё
    if request.user.groups.filter(name="Клиенты").exists():
        return qs.filter(user=request.user)  # Клиент видит только своё
    if request.user.groups.filter(name="Операторы").exists():
        return qs  # Оператор видит всё
    return qs.filter(user=request.user)
```

### Подготовка к ЛК

Ролевая модель готова для интеграции с личным кабинетом:

1. **Клиенты** получают доступ к упрощённому интерфейсу
2. **Операторы** получают доступ к расширенной админке
3. **Суперпользователи** управляют системой


- `requirements.txt` — добавлен django-constance
- `config/settings.py` — интеграция Constance
- `core/models.py` — добавлено поле `script` в Task


## 📚 Примеры использования

### Пример 1: Изменение таймаута

1. Откройте админку
2. Перейдите в Constance
3. Измените `TASK_TIMEOUT_MINUTES` с 60 на 120
4. Сохраните
5. Новые задачи будут использовать таймаут 120 минут

### Пример 2: Добавление нового скрипта

1. Создайте файл `whisper_turbo.py` в `./scripts/`
2. Откройте админку → Скрипты транскрибации
3. Загрузите файл, укажите название "Whisper Turbo"
4. Установите "Скрипт по умолчанию"
5. Теперь все новые задачи будут использовать этот скрипт

### Пример 3: Назначение роли

1. Создайте нового пользователя в админке
2. Добавьте его в группу "Клиенты"
3. Пользователь теперь видит только свои задачи
