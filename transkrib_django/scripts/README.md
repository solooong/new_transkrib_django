# scripts/ — каталог скрипта транскрибации

Сюда кладётся ваш файл распознавания (по умолчанию **`1.py`**). Проект его
**не изменяет** — он подключается в контейнер volume-ом `./scripts:/app/scripts`
и вызывается как внешний процесс.

## Настройка расположения

Положение скрипта задаётся двумя переменными окружения (см. `docker-compose.yml`):

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TRANSCRIBE_SCRIPT_DIR` | `scripts` | **Каталог**, в который кладётся файл скрипта |
| `TRANSCRIBE_SCRIPT_NAME` | `1.py` | **Имя файла** скрипта внутри каталога |

Итоговый путь: `<проект>/scripts/1.py`. Если хотите, например, хранить скрипт
в каталоге `engine` под именем `recognize.py`:

```yaml
environment:
  TRANSCRIBE_SCRIPT_DIR: "engine"
  TRANSCRIBE_SCRIPT_NAME: "recognize.py"
volumes:
  - ./engine:/app/engine   # не забудьте поменять и volume
```

## Контракт вызова (по умолчанию)

```
python scripts/1.py --input <путь к загруженному файлу> --output <папка результатов>
```

- `--input` — файл из `media/uploads/…`
- `--output` — папка `media/results/task_<id>/` (создаётся заранее)
- Всё, что скрипт пишет в stdout/stderr, построчно попадает в журнал задачи
  (уровни info/ok/warn/err — по ключевым словам error/warn/done).
- Прогресс: строки вида `… 47% …` автоматически обновляют прогресс-бар.
- Код выхода `0` → статус «Завершено», иначе → «Ошибка».

## Если у вашего скрипта другие аргументы

Задайте команду целиком переменной `TRANSCRIBE_CMD` в `docker-compose.yml`:

```yaml
environment:
  TRANSCRIBE_CMD: "python scripts/1.py {input} {output}"
```

Плейсхолдеры `{input}` и `{output}` подставляются автоматически.
