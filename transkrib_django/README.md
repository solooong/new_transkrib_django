# Транскриб — веб-интерфейс транскрибации (версия 2)

Лёгковесный веб-интерфейс для запуска внешнего скрипта транскрибации
(`scripts/1.py`) с авторизацией, загрузкой файлов, живыми логами, сохранением
и отображением транскрибаций пользователя и скачиванием результата в `.txt`.
Работает локально в Docker.

**Версия 2:** мониторинг системы удалён. Транскрибацию выполняет отдельный
**Flask-runner**, живущий в том же контейнере: Django передаёт ему задачу по
HTTP, runner запускает скрипт и шлёт журнал/прогресс/результат обратно.

## Быстрый старт

```bash
# 1. Настройте окружение (опционально — всё работает и со значениями по умолчанию)
cp .env.example .env

# 2. Положите ваш скрипт распознавания в папку scripts как 1.py
cp /путь/к/вашему/скрипту.py scripts/1.py

# 3. Соберите и запустите
docker compose up --build

# 4. Откройте http://localhost:8000 (порт — TRANSCRIB_PORT в .env)
#    Вход: admin / admin (или ADMIN_USERNAME / ADMIN_PASSWORD из .env)
```

## Архитектура

```
┌────────────────────────── контейнер transkrib-web ──────────────────────────┐
│                                                                             │
│   Браузер ──HTTP──▶  Django :8000  ──POST /run──▶  Flask-runner :8800       │
│      ▲                 │  (интерфейс, БД,           │  (запускает скрипт,    │
│      │                 │   файлы, скачивание)       │   стримит вывод)       │
│      │                 │                            │                        │
│      │                 ◀──── callback-API ──────────┘                        │
│      │               /api/runner/log|progress|done|error                    │
│      │                    (секрет X-Runner-Secret)                          │
│      │                                  │                                   │
│      └────────── media/ + SQLite ◀──────┘  scripts/1.py  ◀─ volume ./scripts│
└─────────────────────────────────────────────────────────────────────────────┘
```

1. На странице **«Новая задача»** загружаете аудио (mp3/wav/m4a/… до 2 ГБ).
2. Django создаёт задачу и передаёт её runner-у (`POST {RUNNER_URL}/run`).
3. Runner запускает `python scripts/1.py --input … --output media/results/task_<id>/`
   и построчно шлёт вывод в журнал задачи, обновляет прогресс по строкам `NN%`.
4. Код выхода `0` → runner читает транскрипт из папки результатов и передаёт его
   в Django: текст сохраняется в базе, отображается на странице и скачивается `.txt`.
   Другой код → «Ошибка» с кнопкой **«Повторить»**.
5. Дашборд показывает транскрибации пользователя и обновляется автоматически.

## Что внутри

| Компонент | Назначение |
| --- | --- |
| `runner.py` | Flask-runner: эндпоинты `/health`, `/run`; запуск скрипта, стриминг вывода, чтение транскрипта |
| `core/models.py` | `Task` (статус/прогресс/транскрипт/слова), `TaskLog` (построчный журнал) |
| `core/utils.py` | Отправка задачи в runner с ретраями, проверка его доступности |
| `core/views.py` | Страницы + API (frontend и защищённые callback-и runner'а), скачивание `.txt` |
| `static/core/js/` | Скрипты отображения: live-таблица, стриминг лога, индикатор runner'а |
| `seed_demo` | Демо-пользователь и примеры транскрибаций |

## Переменные окружения

Все переменные задаются в **`.env`** (шаблон — `.env.example`). Compose
подставляет их с запасными значениями, поэтому проект работает и без файла.

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TRANSCRIBE_SCRIPT_DIR` | `scripts` | Каталог, куда кладётся файл скрипта |
| `TRANSCRIBE_SCRIPT_NAME` | `1.py` | Имя файла скрипта внутри каталога |
| `MAX_CONCURRENT_TASKS` | `1` | Одновременные запуски скрипта |
| `RUNNER_URL` | `http://127.0.0.1:8800` | Адрес runner'а (для Django) |
| `DJANGO_INTERNAL_BASE` | `http://127.0.0.1:8000` | Адрес Django (для callback'ов runner'а) |
| `RUNNER_SECRET` | dev-секрет | Секрет защиты callback-API. **Смените в продакшене** |
| `RUNNER_PORT_HOST` | `8800` | Порт runner'а на хосте (отладка `/health`) |
| `TRANSCRIB_PORT` | `8000` | Порт интерфейса на хосте |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / `admin` | Учётка первого старта |
| `DJANGO_DEBUG` | `1` | Режим отладки |
| `DJANGO_SECRET_KEY` | dev-ключ | **Обязательно задайте в продакшене** |

## Полезное

- Проверить runner: `curl http://localhost:8800/health`
- Логи Django: `logs/django.log` (volume, ротируются по 5 МБ).
- Админка Django: `http://localhost:8000/admin/`.
- `1.py` проектом не модифицируется — просто заменяйте файл в `./scripts`,
  он подхватится при следующем запуске задачи (перезапуск контейнера не нужен).
- Для продакшена: `DJANGO_DEBUG=0`, свои `DJANGO_SECRET_KEY` и `RUNNER_SECRET`,
  gunicorn вместо runserver.
